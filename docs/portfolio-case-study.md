# AI 错题本｜项目案例与面试证据

## 一句话定位

一个将“错题内容”转化为“可追问的错因诊断与薄弱点归纳”的 AI 学习产品 MVP。重点不在替学生直接给答案，而在用结构化诊断区分知识盲区、题型不熟与计算粗心等可行动问题。

线上体验：[ai-mistake-notebook.vercel.app](https://ai-mistake-notebook.vercel.app)

## 我解决的产品问题

传统错题本通常只保存题目与答案，学生仍不清楚“自己为什么会错”、下一次应如何练习。本项目把一次错题复盘拆成三步：

1. 录入题干、错误作答与学科背景；
2. 通过多轮追问补充推理过程；
3. 输出错因、知识点、学习状态和下一步练习建议，并在薄弱点地图中聚合。

## 核心方案

| 问题 | 方案 | 验证方式 |
| --- | --- | --- |
| 自由文本输出不稳定 | 后端要求模型返回 JSON，并做字段校验、失败重试与 fallback | `evaluation/latest-report.json` 的结构化输出率 |
| 只靠一次回答难以判断错因 | 将诊断设计为 2–3 轮追问，收集思路而非只看答案 | 线上诊断页可完整演示 |
| AI 产品难以复盘模型表现 | 接入 Langfuse，记录模型、轮数、延迟、重试及结构化校验结果 | Langfuse Trace 与自建评测关联 |
| 学习内容敏感 | 线上版只记录匿名流程事件；题干、作答、追问原文默认保留在浏览器 | `supabase/analytics-only-schema.sql` 与 README 隐私说明 |

## 可核验结果

- 基于 24 条自建标注样例，覆盖小学至高中、数学/语文/英语/物理/化学等错因场景。
- 最近一轮评测：结构化输出 **24/24**；错因分类 **23/24**；状态识别 **24/24**；平均端到端耗时 **4.53 秒**。
- 其中 1 条错因分类不一致被保留在报告中，作为后续 Prompt、标签边界与复核策略的优化样例；以上均为离线自建评测，不代表真实用户数据或留存。
- 已上线可运行 MVP，含录入、追问诊断、错因归纳、薄弱点地图和匿名事件漏斗。

## 3 分钟演示路径

1. 打开首页，录入一条示例错题并选择学科；
2. 进入诊断页，完成三轮追问，展示 JSON 驱动的错因、知识点与建议；
3. 打开归纳页与薄弱点地图，说明如何从单题复盘过渡到知识点聚合；
4. 在 Langfuse 展示一次 Trace：模型调用、延迟、重试与结构化校验；
5. 说明隐私边界：线上数据库只写匿名事件，原始学习内容不入库。

## 我会如何继续迭代

1. 为错因标签增加置信度阈值和人工复核队列，优先处理低置信度/争议标签；
2. 接入真正的 OCR 上传链路，并将图片、文本确认与诊断拆成可观测漏斗；
3. 当有真实用户和授权后，再基于实际事件定义诊断完成率、P95 耗时和复访率；当前不以自建评测冒充用户指标。

## 面试高频追问口径

**为什么要用 Langfuse？**

因为 LLM 产品的“能跑”不等于“可维护”。我需要知道哪类输入触发了重试、结构化输出是否稳定、延迟在哪里波动。Langfuse 记录的是模型调用的摘要与运行指标，不记录学生题干或追问原文。

**23/24 不是满分，为什么保留？**

因为错误样本最有价值。那条物理样例暴露的是标签边界问题：模型将题目理解为知识盲区，而预期标签定义为题型不熟。我不会把它改成“满分”，而会将其纳入标签定义与 Prompt 迭代的回归样例。

**为什么不把所有数据放到云端？**

学习题目和作答属于敏感内容。作品集阶段并不需要以牺牲隐私换取“有数据库”的展示，因此线上版只存匿名流程事件；未来接入账户体系时，再在授权、RLS 和数据生命周期策略下讨论云端存储。
